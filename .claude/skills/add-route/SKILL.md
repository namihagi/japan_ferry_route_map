# 航路を追加・照合する

用語は [`CONTEXT.md`](../../../CONTEXT.md)、台帳の書き方は [`data/README.md`](../../../data/README.md) に従う。1回の作業では、運航会社単位でまとめて進める。

この手順の要は **2 の照合** で、そこだけが人の判断を要する。1・3・5 は機械にやらせる。

## 1. 対象を選び、下書きを作る

未収録の航路は [`docs/coverage.md`](../../../docs/coverage.md) に並んでいる（`pnpm data:survey-osm` が OSM から生成する）。ここから運航会社を選ぶ。進める順序は [`docs/spec.md`](../../../docs/spec.md) の「航路を増やす順序」にある。

```sh
pnpm data:draft --operator 中島汽船     # OSM の operator タグで選ぶ
pnpm data:draft --name 伊勢湾フェリー    # operator タグがない候補は名称で選ぶ
pnpm data:draft --way 30263603          # way を直に指定する
```

`.cache/drafts/` に航路の下書きと `ports.yaml`（新しい港の候補）が出る。下書きには OSM から推測した値と `TODO` が入っている。`.cache/` に出すのは、照合前のものを公開データと混ぜないため（`CLAUDE.md` のガードレール2）。

CONTEXT.md の「対象航路」に当てはまらないものは、ここで落とす。

- 貨物フェリー（一般の旅客が乗れない）、周遊型の遊覧船、国際航路、廃止済みの航路は入れない。
- OSM の `route=ferry` には湖の遊覧船やテーマパークの乗り物も混ざっている。
- 同じ会社でも船種が違えば別の航路にする（例：フェリーと高速船）。

**完了の条件**：追加する航路の下書きが `.cache/drafts/` にある。

## 2. 公式サイトで照合する

運航会社の公式サイトで、次の5項目を確かめ、下書きを直す。

1. 航路名（OSM の名称ではなく、運航会社が使っている航路名にする）
2. 運航会社（正式名称から「株式会社」などを除く）
3. 寄港地（下書きの並びが正しいか。下書きは OSM の線のつながりから作った推測）
4. 船種（車を積めるか。高速船か。下書きの `vesselType` は OSM の車の可否からの推測で、高速船かどうかは判定できていない）
5. 運航状態（運航中／休止中）

補足：

- 「休航」「運休」が一時的な欠航（天候・ドック入り）なら運航中のまま。航路そのものの休止なら `suspended` にし、`note` に根拠を書く。
- 所要時間は、公式サイトに書いてあるときだけ `durationMinutes` に入れる。
- 公式サイトに載っていない航路は、廃止の可能性があるので追加しない。
- 取得のコツ：ページ全体を読むより、`curl` で取得して上の項目のキーワード周辺だけを抜き出すほうが速い。つながらないときは URL の誤り（ハイフンの有無など）と TLS の中間証明書の欠落を疑う。後者は `curl -k` で読める。
- 寄港地と船種は、トップページより時刻表や運航案内のページのほうが文字で読みやすい。

**完了の条件**：5項目すべてについて、根拠となる公式ページの URL を `verification.sources` に書ける。

## 3. 台帳に移す

- **港**：`.cache/drafts/ports.yaml` の港のうち、台帳にまだないものを `data/ports.yaml` に追記する。
  - `id` が `todo-N` の港は、自分で英小文字の ID を付ける。読みが近い港（直島の宮浦と屋久島の宮之浦など）は島名を頭に付けて区別する。
  - `name` は旅客が呼ぶ単位にする。OSM から来た「〇〇フェリーターミナル」のような名前は「〇〇」に直す。同じ名前で呼ばれる港は、ターミナルが 1〜2 km 離れていても1つにする。
- **航路**：下書きの `TODO` を埋め、`data/routes/<id>.yaml` に移す。`id` は `<会社>-<港>-<港>` のように英小文字とハイフンで付ける。
- **区間**：`osmWays` は下書きが割り当てている。OSM に線がない区間は `osmWays` を書かない（推定形状になる）。下書きが「線が2本ある」と注意していたら、1本に絞る。

**完了の条件**：`data/routes/` と `data/ports.yaml` に `TODO` が残っていない。

## 4. データを作って確かめる

```sh
pnpm data:import-osm   # OSM API から way を取り込む
pnpm data:estimate     # 推定形状の区間があれば（data/README.md「推定形状」）
pnpm data:build        # 台帳の誤りや、港と線のずれがあればここで失敗する
```

推定形状を新しく計算した区間は、陸を横切っていないか、不自然に遠回りしていないかを目で確かめる。

**完了の条件**：`pnpm data:build` が通り、新しい推定形状をすべて目で確かめた。

## 5. PR にする

- まとまった数（10〜30航路程度）ごとにブランチを切って PR にする。
- PR の本文には、照合した航路の一覧（航路・運航会社・運航状態・形状の出どころ）と、照合で判断に迷った点を書く。
- マージしたら `pnpm data:survey-osm` を実行し直し、`docs/coverage.md` の収録済みの数を更新する。
