# 推定形状の計算だけは Python で書く

プロジェクトは TypeScript で統一しているが、推定形状（海上だけを通る最短経路）を計算するスクリプトだけは Python で書き、`tools/` 配下に隔離して uv で管理する。この計算では、陸地ポリゴンをマス目に変換し（ラスタライズ）、グリッド A* で経路を探し、得た線が陸地を横切っていないか検証する。こうした処理は Python のライブラリ（shapely、rasterio、scikit-image）が成熟している。TypeScript で書くと、GDAL のコマンドラインツールを外から呼びつつ A* や検証を自前で書くことになり、正しさの担保が難しい。TypeScript 側とのやり取りは GeoJSON ファイルだけなので、言語が混ざるコストは小さい。

## Considered Options

- **既製の海上経路ライブラリ**（Eurostat SeaRoute、searoute-js、scgraph）：使わない。いずれも MARNET という航路網を使うが、この航路網は瀬戸内海全体でも頂点が33個しかなく、島を渡る短い区間を描けない。
- **可視グラフ**：使わない。海岸線の頂点数が多すぎて計算が終わらない。頂点を間引けば計算は回るが、今度は狭い海峡が閉じてしまう。
