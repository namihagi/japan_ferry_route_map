# 初版の仕様

初版で作るもの、作らないもの、データの作り方をまとめる。用語の意味は [`CONTEXT.md`](../CONTEXT.md)、判断の理由は [`docs/adr/`](./adr/) にある。ここに書くのは、そのどちらにも入らない決定だけ。

## 位置づけ

- 個人の趣味サイトとして作り、GitHub Pages で一般公開する。
- 情報の正確さはベストエフォートとし、出典をきちんと表記する。実際の運航情報は、各運航会社の公式サイトで確認してもらう前提。
- PC とスマホの両方で使えるようにする（レスポンシブ）。表示言語は日本語だけ。

## 画面と機能

### 地図

- 背景地図は、国土地理院の地理院タイル（淡色地図）。
- 拡大・縮小・スクロールなど、一般的な地図の操作ができる。

### 航路線

- 航路形状は区間ごとに描く。
- 色は船種で分ける（フェリー、高速船、旅客船の3色）。
- 休止中の航路はグレーで描く。
- 推定形状の区間は点線で描き、実測形状（実線）と見分けられるようにする。

### 航路の詳細

航路線をクリック（タップ）すると、詳細を表示する。

- クリックした場所に航路が1本しかなければ、すぐに詳細を出す。
- 複数の航路が重なっていれば、まず航路の一覧を出して選んでもらう。
- 詳細に表示する項目：
  - 航路名、運航会社
  - 寄港地（順序付き）
  - 船種
  - 運航状態、季節運航の注記
  - 公式サイトへのリンク
  - 所要時間（取れる場合だけ）

### 絞り込み

絞り込みの軸は、船種・運航状態・運航会社の3つ。

### 港

- ある程度拡大したときだけ、港の点と港名を表示する。日本全体を表示しているときは、航路線だけを出す。
- 港をクリックすると、その港に発着する航路をハイライトする。

### 出典表示

地図上に次の2つを常に表示する。

- © OpenStreetMap contributors
- 国土地理院

## 範囲外

初版では、次のものは作らない。

| 分類 | 作らないもの |
|---|---|
| 運航情報 | 便数、運賃、時刻表 |
| 機能 | 地域での絞り込み |
| 対象 | 国際航路、廃止済みの航路、遊覧船、貨物フェリー（`CONTEXT.md` の「対象航路」を参照） |
| 表示言語 | 多言語対応 |
| モデル化の細かさ | ターミナル単位の区別、便ごとの寄港の違い |

次の2つは第2段階の候補として残しておく。

- 港名・航路名での検索
- 航路一覧と地図の連動

表示位置や航路を共有できる URL（パーマリンク）は、第2段階の候補から前倒しして作った（下の「パーマリンク」）。

## データの作り方

### 航路台帳と港台帳

- 航路台帳は、1航路を1つの YAML ファイルにする。
- 港は港台帳に分けて持ち、航路台帳の寄港地から参照する。
- 台帳の内容は、運航会社の公式サイトを出典にする。
- 地図に公開するのは照合済みの航路だけ。

### 下書きを作る

- 航路台帳の下書きは、OSM の `route=ferry` の線とそのタグから一括で生成する（`pnpm data:draft`）。
  - つながる線から寄港地の並びを組み立て、区間ごとに way を割り当てる。船種は車の可否から推測する。
  - 枝分かれしていてつなげない候補は、線ごとの下書きに分けて注意を出す。
- 港の座標の下書きは、OSM の `amenity=ferry_terminal` から作る。OSM にローマ字表記がない港は、ID を `todo-N` にして人が付ける。
- どちらも `.cache/drafts/` に書き、照合するときに公式サイトと突き合わせて確認してから台帳に移す。

### 網羅性の確認

- `pnpm data:survey-osm` が OSM の `route=ferry` を全国分取得し、台帳と突き合わせて候補一覧 [`coverage.md`](./coverage.md) を作る。取得した生データは `.cache/osm-survey/` に置く。
- 調べて「対象航路ではない」と判断した線は `data/excluded.yaml` に記録し、分母から外す。記録しないと、セッションが変わるたびに同じ線を調べ直すことになる。
- 国土数値情報 N09（定期旅客航路）は、手元で網羅性を確認するための参照にだけ使う。
- N09 は `.cache/` に置き、リポジトリには入れない（ADR 0001）。

### 航路形状

**実測形状**

- 航路台帳の区間は、OSM の way ID を参照する。
- OSM の線は手動で取り込み、スナップショットとしてコミットする（ADR 0003）。

**推定形状**

実測形状がない区間は、推定形状を計算する。計算は Python で行う（ADR 0002）。

- **陸地のデータ**：OSM land polygons（ODbL）。
- **計算方法**：マス目の上で、海のマスだけを通る最小コストの経路を探す。
  - 短い区間は、区間の周囲全体を細かいマス目にして一度に探す。マス目は通常約40m、30km 未満の区間では約20m。
  - 細かいマス目ではマスが多すぎる長い区間は、2段階で探す。
    - まず約450m のマス目で大まかな経路を出し、見通しの利く範囲で直線にする。粗いマスは、中の約150m のマスが1つでも海なら通れるとし、狭い海峡を閉じないようにする。
    - 大まかな経路を約50km ごとに区切り、それぞれの周囲（幅約5km の回廊）だけを細かいマス目で探し直す。見つからなければ回廊を約15km に広げる。
    - それでも見つからなければ、区間全体をマス数の上限に収まる最も細かいマス目で探し、警告を出す。
  - 陸から約150m 以内のマスは通りにくくし、線が岸に張り付かないようにする。マスより小さい島にかかるマスも通りにくくする。
- **仕上げ**：
  - 見通しの利く部分を直線化して平滑化する。直線にしても元の経路より陸に近づかない範囲だけをつなぐ。
  - 陸地ポリゴンと突き合わせて、陸を横切っていないか検証する。横切る長さが50m を超えたら警告を出し、目視で確認する。
- **港が陸地扱いになる場合**：港が川の中や港湾の奥にあって陸地扱いになるときは、最寄りの海のマスへ寄せる。寄せた距離が500m を超えたら警告を出し、目視で確認する。
- **既知の限界**：
  - 防波堤は陸地ポリゴンに含まれないことがあるので、線が防波堤を横切る場合がある。
  - 浅瀬や航行ルールは考慮しない。

## 技術構成

| 項目 | 採用 |
|---|---|
| ランタイム | Node 24 LTS |
| パッケージ管理 | pnpm 11 |

## 進め方（2026-09-13 に決めたこと）

航路をどこまで網羅するかについて、持ち主から「可能な限り多くの航路を含めたい。優先度はエージェントが付けて順に進め、区切りのよいところで PR を出して公開する」という方針が示されている。そのうえで、次を決めた。

### 照合は5項目のまま維持する

`add-route` スキルのとおり、航路名・運航会社・寄港地・船種・運航状態の5項目を公式サイトで確かめたものだけを公開する。項目を減らして速くする案（存在・運航会社・寄港地の3項目）は採らない。船種を落とすと地図の色分けが崩れ、この地図の見どころが弱くなるため。

速度は、項目を減らすのではなく、照合の前後を機械化して上げる。

### データの網羅を機能追加より優先する

網羅が目標の7〜8割に達するまでは、機能追加よりデータを優先する。ただしパーマリンクだけは先に作る。共有できる URL がないと、公開しても人に見せにくいため。

### 次に進める順序

2. ~~**台帳の下書きを自動生成する**~~：完了。`pnpm data:draft --operator <会社名>` が候補一覧から航路台帳と港台帳の下書きを `.cache/drafts/` に書き出す。下書きはリポジトリに置かない（照合前のものを公開データと混ぜないため）。エージェントの仕事は「公式サイトで5項目を確かめ、`TODO` を埋めて台帳に移す」に絞った。

### 分母の把握（2026-09-13）

- OSM の way 763 本 → 候補 616 件。うち台帳に入っているのは 98 件、未収録は 507 件（2026-09-13 の最初の調査時点。最新の数は [`coverage.md`](./coverage.md) を見る）。
- 未収録のうち 318 件は OSM に `operator` タグがない。運航会社を自分で調べる必要がある。

### パーマリンク

表示位置と選んだ航路を URL のハッシュに持たせる。GitHub Pages は静的配信なので、サーバ設定のいらないハッシュにする。

- 形は OpenStreetMap に合わせて `#map=<zoom>/<lat>/<lon>`。航路を選んでいるときは `&route=<航路 ID>` を足す。
- 地図を動かしたときと、航路を選んだ・閉じたときに書き換える。履歴は汚さない（`replaceState`）。
- 航路だけを指定した URL（`#route=<航路 ID>`）を開くと、その航路に地図を寄せて詳細を出す。そのために公開データの航路ごとに範囲（`bounds`）を持たせている。
- 読めない値は捨てて、地図は普通に出す。航路 ID は台帳と同じ形（英小文字・数字・ハイフン）のものだけ受け取る。
- 絞り込みの状態は URL に入れない。仕様の「パーマリンク」は表示位置と航路だけを対象にしている。

### 保留にした判断

次の3つは、必要になった時点で持ち主に確認する。勝手に進めない。

- **廃止航路の記録**：地図には出さないが、台帳には `status: discontinued` で残すか。残すなら `CONTEXT.md` の「廃止済みの航路は含まない」を「地図には出さないが台帳には残す」に改める必要がある。
- **リンク切れの定期チェック**：`verification.sources` の URL に定期的に触り、切れていたら Issue を立てるワークフロー。作るなら `CLAUDE.md` のガードレール「定期実行のワークフローは作らない」を「データを書き換える定期実行は作らない」に直す必要がある。
- **フォント配信の自前化**：港名の描画に使っている地理院のグリフ配信（`maps.gsi.go.jp/xyz/noto-jp`）が止まると港名が消える。書体を `public/` に持てば解決するが、リポジトリにフォントを入れる構成変更になる。

### 照合の記録について

`verification.sources` には、確かめたページ（時刻表・航路案内など）の URL を書く。トップページの URL だけだと、再照合のときに何をどこで確かめたのか辿れない。
