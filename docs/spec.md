# 初版の仕様

初版で作るもの、作らないもの、データの作り方をまとめる。用語の意味は [`CONTEXT.md`](../CONTEXT.md)、判断の理由は [`docs/adr/`](./adr/) にある。ここに書くのは、そのどちらにも入らない決定だけ。

## 位置づけ

- 個人の趣味サイトとして作り、GitHub Pages で一般公開する。
- 情報の正確さはベストエフォートとし、出典をきちんと表記する。実際の運航情報は、各運航会社の公式サイトで確認してもらう前提。
- PC とスマホの両方で使えるようにする（レスポンシブ）。表示言語は日本語だけ。

## 画面と機能

### 地図

- 背景地図は、国土地理院の地理院タイル（淡色地図）。
- 拡大・縮小・スクロールなど、一般的な地図の操作ができる。

### 航路線

- 航路形状は区間ごとに描く。
- 色は船種で分ける（フェリー、高速船、旅客船の3色）。
- 休止中の航路はグレーで描く。
- 推定形状の区間は点線で描き、実測形状（実線）と見分けられるようにする。

### 航路の詳細

航路線をクリック（タップ）すると、詳細を表示する。

- クリックした場所に航路が1本しかなければ、すぐに詳細を出す。
- 複数の航路が重なっていれば、まず航路の一覧を出して選んでもらう。
- 詳細に表示する項目：
  - 航路名、運航会社
  - 寄港地（順序付き）
  - 船種
  - 運航状態、季節運航の注記
  - 公式サイトへのリンク
  - 所要時間（取れる場合だけ）

### 絞り込み

絞り込みの軸は、船種・運航状態・運航会社の3つ。

### 港

- ある程度拡大したときだけ、港の点と港名を表示する。日本全体を表示しているときは、航路線だけを出す。
- 港をクリックすると、その港に発着する航路をハイライトする。

### 出典表示

地図上に次の2つを常に表示する。

- © OpenStreetMap contributors
- 国土地理院

## 範囲外

初版では、次のものは作らない。

| 分類 | 作らないもの |
|---|---|
| 運航情報 | 便数、運賃、時刻表 |
| 機能 | 地域での絞り込み |
| 対象 | 国際航路、廃止済みの航路、遊覧船、貨物フェリー（`CONTEXT.md` の「対象航路」を参照） |
| 表示言語 | 多言語対応 |
| モデル化の細かさ | ターミナル単位の区別、便ごとの寄港の違い |

次の3つは第2段階の候補として残しておく。

- 港名・航路名での検索
- 航路一覧と地図の連動
- 表示位置や航路を共有できる URL（パーマリンク）

## データの作り方

### 航路台帳と港台帳

- 航路台帳は、1航路を1つの YAML ファイルにする。
- 港は港台帳に分けて持ち、航路台帳の寄港地から参照する。
- 台帳の内容は、運航会社の公式サイトを出典にする。
- 地図に公開するのは照合済みの航路だけ。

### 下書きを作る

- 航路台帳の下書きは、OSM の `route=ferry` の線とそのタグから一括で生成する。
- 港の座標の下書きは、OSM の `amenity=ferry_terminal` から作る。
- どちらも、照合するときに公式サイトと突き合わせて確認する。

### 網羅性の確認

- 国土数値情報 N09（定期旅客航路）は、手元で網羅性を確認するための参照にだけ使う。
- N09 は `.cache/` に置き、リポジトリには入れない（ADR 0001）。

### 航路形状

**実測形状**

- 航路台帳の区間は、OSM の way ID を参照する。
- OSM の線は手動で取り込み、スナップショットとしてコミットする（ADR 0003）。

**推定形状**

実測形状がない区間は、推定形状を計算する。計算は Python で行う（ADR 0002）。

- **陸地のデータ**：OSM land polygons（ODbL）。
- **計算方法**：2段階のグリッド A* で経路を探す。
  - まず約450m のマス目で大まかな経路を出し、その周囲に回廊を作る。
  - 回廊の中だけを細かいマス目で探し直す。マス目は通常約40m、30km 未満の区間では約20m。
  - 陸から約150m 以内のマスは通りにくくし、線が岸に張り付かないようにする。
- **仕上げ**：
  - 見通しの利く部分を直線化して平滑化する。
  - 陸地ポリゴンと突き合わせて、陸を横切っていないか検証する。
  - 約20m で線を単純化する。
- **港が陸地扱いになる場合**：港が川の中や港湾の奥にあって陸地扱いになるときは、最寄りの海のマスへ寄せる。寄せた距離が500m を超えたら警告を出し、目視で確認する。
- **既知の限界**：
  - 防波堤は陸地ポリゴンに含まれないことがあるので、線が防波堤を横切る場合がある。
  - 浅瀬や航行ルールは考慮しない。

## 技術構成

| 項目 | 採用 |
|---|---|
| ランタイム | Node 24 LTS |
| パッケージ管理 | pnpm 11 |
| ビルド | Vite 8 |
| 言語 | TypeScript 6.0（UI フレームワークは使わない） |
| リントと整形 | Biome 2 |
| テスト | Vitest（ロジック）、Playwright（最小限の E2E） |
| 地図 | MapLibre GL JS 6（Vite では `setWorkerUrl` の設定が必要） |
| 推定形状の計算 | Python（uv で管理。shapely、rasterio、scikit-image） |
| デプロイ | GitHub Actions → GitHub Pages（configure-pages v6、upload-pages-artifact v5、deploy-pages v5） |

公開 URL は `https://namihagi.github.io/japan_ferry_route_map/` になる。そのため Vite の `base` は `/japan_ferry_route_map/` にする。
